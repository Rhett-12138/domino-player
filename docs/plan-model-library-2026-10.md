# 评估：模型库 + 真人/动画选择（2026-10）

> 状态：**第一层已实现**（2026-10-18）。任务中心已有“内容类型：真人/实拍 / 动画”，
> 复用现有 General x4 与 animevideov3 x4；模型写入 `meta.tsv` 并在续编沿用。
> 第二层高质量模型和 2x/3x 仍待评估。
>
> 结论：**先加“内容类型”下拉（真人 / 动画），复用现有两个模型，零新模型资产即可上线；**
> 之后再补高质量模型和 2x/3x。真人/动画模型差异明显，值得让用户选，不建议做自动识别。

## 现状

- 已有模型（`assets/models/sr/ncnn/`）：
  - `RealESRGAN_General_x4_v3`：2.4MB，通用/真人，当前离线与实时默认。
  - `realesr-animevideov3-x4`：1.2MB，动画视频专用。
- 离线编码 `encodeOffline` 仍硬编码 `RealESRGAN_General_x4_v3`；
- `Config::srParam()/srBin()` 也固定通用模型；
- 任务参数目前只有目标分辨率 + 质量档，没有内容类型。

## 实测：动画模型 vs 通用模型

同一 720p 测试源、4x、FullSource：

| 指标 | 通用 x4 v3 | 动画 x4 | 差异 |
|---|---:|---:|---:|
| 直接 SR 1080p | 24.1ms | **18.1ms** | 1.33x 快 |
| 直接 SR 2K | 50.0ms | **35.3ms** | 1.42x 快 |
| 直接 SR 4K | 121.6ms | **84.6ms** | 1.44x 快 |
| 离线 2s 720p→1080 Full | 15.3s | **11.0s** | 1.39x 快 |
| 模型大小 | 2.4MB | **1.2MB** | 小一半 |

> 速度差异明确；画质必须用真人/动画两类素材做 A/B。测试图（彩条）不能判断“真人脸是否被动画模型涂抹”。

## 建议的模型库分层

### 第一层：立即可用（现有资产，无需新增）

| 内容类型 | 默认模型 | 定位 |
|---|---|---|
| **真人/实拍** | `RealESRGAN_General_x4_v3` | 通用，保留纹理；当前默认 |
| **动画** | `realesr-animevideov3-x4` | 线条/色块更干净，速度更快 |

优点：**零新增模型文件**，UI/持久化/回退改完即可上线；风险最低。

### 第二层：高质量可选（按需增加）

| 内容类型 | 候选 | 大小 | 特点 | 风险 |
|---|---|---:|---|---|
| 真人 | `RealESRGAN_x4plus` | ~64MB | 纹理/细节更强，但慢 2–3x | 包体大；需要 NCNN 转换/验证 |
| 动画 | `RealESRGAN_x4plus_anime_6B` | ~10–17MB | 线条/细节更好，速度慢于 animevideov3 | 包体中等；需验证 |
| 动画 | Real-CUGAN 2x/3x/4x | 每个 5–10MB | 降噪强，适合旧番/压缩源 | 有多个 denoise 变体；真人可能过度平滑 |
| 真人/通用 | Real-ESRGAN x2plus | ~64MB | 1080→4K 正好 2x，速度快 | 需转换/验证；见 scale 分析 |

> 全部打包会增加约 **100–150MB**；建议只默认带第一层，第二层做“可选模型包/下载”，
> 或在安装包里提供精简/完整两个版本。

### 不建议

- **1.5x 原生模型**：没有主流现成模型；用 2x + Lanczos 缩到 1.5x 即可。
- **自动识别真人/动画**：误判成本高（把真人当动画会涂抹），用户手动选更可靠；
  后续如果做，也只作为“推荐”，不强制。

## 推荐 UI

新建任务对话框：

```
输出分辨率：720p / 1080p / 2K / 4K
超分质量：快速 / 平衡 / 高质量
内容类型：真人/实拍 / 动画
```

- 默认：真人/实拍 + 高质量；
- 动画选项使用动画模型，速度更快；
- 任务卡片显示模型名，便于知道产物用了哪个；
- 模型缺失时：
  - 禁止该选项或自动回退通用模型；
  - 显式提示“动画模型不可用，已用通用模型”，不静默降级。

## 持久化/接口

建议不要只把模型写进 `EncodeOptions`，还要写进任务：

- `Task::modelId`（`"realistic"` / `"anime"`）；
- `meta.tsv` 第三行：`model=realistic` / `model=anime`；
- 旧任务缺字段 → 默认 `realistic`；
- 续编必须沿用原模型，避免合并处画风跳变；
- `domino_task_create_ex` 增加 `modelId` 参数（或在现有 quality 参数后追加）。
- `EncodeOptions` 增加 `modelId`，`encodeOffline` 按注册表解析 param/bin；
- `Config` 保留默认通用模型，保证实时播放/旧调用兼容。

## 推荐路线

1. **先做第一层**：内容类型下拉 + 现有两个模型；默认真人；meta 持久化；任务卡片显示。
   - 成本最低，立刻改善动画/真人错配。
2. **用用户素材盲测**：真人脸、动画线稿、文字各一组；确认动画模型在真人上不涂抹。
3. 再决定是否加入 `x4plus` / `anime_6B` 高质量档。
4. 模型 scale（2x/3x）按 `docs/plan-sr-model-scales-2026-10.md` 单独推进；1.5x 用 2x 模拟。
