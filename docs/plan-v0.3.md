# Domino Player V0.3 规划（2026-10）

> 前置版本：v0.2.4。  
> 默认范围：**Windows 桌面产品化**。移动端放入 V0.4，不在 V0.3 主线里硬塞。
>
> 一句话目标：**把“能跑、帧率高”变成“普通用户敢装、不同机器能跑、出问题能定位”。**

## 一、为什么不是继续追 4K 60

V0.2 已经完成：

- 4K 零拷贝播放约 30 FPS（RTX 4070 SUPER / 720p 源）
- 自动降档、竖屏/超宽、美颜切换、任务中心 HQ 回归
- TensorRT/NCNN 双后端和 CPU 回退

继续做 4K 60、微秒级 copy 优化的收益已经明显变小；真正阻碍用户使用的是：

1. **硬件/驱动差异**：混合显卡、AMD/Intel、旧驱动、cudart/TensorRT 缺失时体验不一致。
2. **分发形态**：只有 zip、未签名、235MB、首次 engine 构建 12–20s。
3. **可诊断性**：用户只知道“卡”，我们不知道是 SR、D3D、音频还是驱动。
4. **画质/模型覆盖**：真人 2x/3x 缺失，x4plus HQ 慢，4K 离线峰值内存高。
5. **回归成本**：零拷贝/混合显卡/长稳缺少自动化和真实硬件矩阵。

## 二、V0.3 目标与非目标

### 目标

- 推出一版**可长期日常使用的 Windows 桌面版**（V0.3.0）。
- 在 NVIDIA / AMD / Intel 和混合显卡上都有**明确、可解释的降级路径**，不黑屏、不慢放、不静默变卡。
- 提供安装/绿色包、版本与诊断信息、崩溃/失败日志。
- SR 慢时保持 1x 播放（跳帧而不是慢放）；自动降档策略稳定。
- 离线任务在 4K FullSource 下内存可控，HQ 可完成。

### 非目标（V0.3 不做或只做技术预研）

- Android/iOS 完整端（只做可移植性 spike）。
- 4K 60 / 8K 实时。
- 在线模型商店、账号、云同步。
- 完整的剪辑/转码工作站功能。
- 所有 AMD/Intel 机器都实现零拷贝 GPU 输出（先保证 NCNN/CPU 路径可用）。

## 三、优先级

### P0：兼容性与可诊断性（最高优先级）

**要解决的问题**：同一版本在用户机器上“有时能跑、有时黑屏/慢放/闪退”，却无法判断原因。

工作项：

1. **GPU/后端能力探测**
   - 在桥层探测：D3D11 adapter、厂商、驱动版本、CUDA/cudart、TensorRT engine 状态、Vulkan、H.264 硬解。
   - 启动时输出一份 `diagnostics.json` / 设置页“关于/诊断”展示。
   - 明确标记当前路径：`TensorRT + zero-copy` / `TensorRT + CPU output` / `NCNN` / `CPU fallback`。

2. **统一降级策略**
   - 只在用户层暴露 **自动 / 兼容 / 性能** 三档，不暴露 TensorRT/CUDA 细节。
   - 自动档：尝试 TensorRT/零拷贝；失败自动回退并记录一次原因。
   - 兼容档：跳过 TensorRT/零拷贝，直接 NCNN/CPU。
   - 性能档：优先 NVIDIA + TensorRT + 零拷贝；混合显卡上明确提示可能黑屏，或自动检测 Flutter adapter。
   - 所有降级必须**显示一次**原因，而不是静默从 30 FPS 变 23 FPS。

3. **混合显卡真实矩阵**
   - 至少一台“核显为默认 adapter”的笔记本实测。
   - 验证 `DOMINO_D3D_ADAPTER=default`、共享纹理失败、Flutter 光栅线程回退。
   - 目标：最坏情况黑屏可自动恢复为 CPU 输出，不允许整个播放页不可用。

4. **长稳与资源**
   - 1 小时 4K 零拷贝循环、切档、seek、美颜开关、任务边播。
   - 监控 VRAM/句柄/线程；确认 cudart 资源、D3D input slot、output descriptor 不增长。
   - 增加 zero-copy slot 生命周期测试（seek/丢帧/失败/close）。

### P0：Windows 产品化

1. **安装包 / 绿色包**
   - 绿色 zip 保留；新增安装包（Inno Setup 或等价工具，构建期外置）。
   - 安装时检测 VC++ Runtime；缺失时给出明确提示或随包安装。
   - 文件关联（可选）、开始菜单、卸载。
2. **可选组件**
   - 评估把 TensorRT-RTX 220MB 拆成“高性能组件”，安装器/设置页可下载；基础包保持可播放。
   - 若拆包，必须保证缺组件时自动 NCNN，不影响启动。
3. **签名与 SmartScreen**
   - 评估代码签名证书；至少提供 SHA256、版本号和发布说明。
   - 未签名时在 README/首次启动明确提示。
4. **诊断与反馈**
   - 本地崩溃/异常日志（D3D device removed、TensorRT init、cudart、音频设备）。
   - “复制诊断信息”按钮，避免用户只发“卡”。
   - 暂不做自动上传遥测，坚持离线。

### P1：画质、模型与离线任务

1. **真人 2x/3x**
   - 继续验证 Real-ESRGAN x2plus / BSRGAN2X 的 NCNN 移植和速度；
   - 若都不合适，明确“真人只支持 4x + 输出缩放”，不要无限尝试。
2. **HQ 模型体验**
   - x4plus / x4plus-anime 在任务中心提供耗时预估和内存提示。
   - 离线 FullSource 4K 做 **tile + overlap**，降低 7680×4320 中间帧峰值（当前约 1.9GB）。
3. **模型包管理**
   - 模型清单、校验和、版本、可选下载/本地导入；
   - 未下载时明确提示，不把“模型缺失”表现成 SR 失败黑盒。

### P1：播放核心补强（按用户价值取舍）

- 硬件解码（D3D11VA/NVDEC）：优先解决高码率 4K 的 CPU 解码瓶颈。
- 音轨/字幕选择：当前只支持默认音轨；这是日常播放器的高频需求。
- 记忆音量、窗口位置、播放速度、快捷键。
- HDR/色彩管理：先评估片源和 D3D 输出支持，不承诺 V0.3 完成。

### P2：移动端 spike（不阻塞 V0.3 发布）

- Android：注入 `AudioSink`、Flutter 纹理/GPU surface、NCNN Vulkan 后端最小闭环。
- 不改引擎协议；只验证 `domino_core` 可移植性。
- 真正的移动端产品放 V0.4。

## 四、建议里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| M0（1–2 周） | 能力探测、诊断页、降级原因、混合显卡矩阵 | 所有机器都有明确 backend/fallback 状态 |
| M1（2–3 周） | 安装包、VC runtime、可选 TensorRT 组件、签名评估 | 可安装的 Windows V0.3 beta |
| M2（2–3 周） | zero-copy/长稳测试、tile 4K、2x/3x 评估 | 4K 任务内存与稳定性达标 |
| M3（1–2 周） | 1h soak、真实片源 A/B、发布检查 | V0.3.0 |

建议先做 M0，不要先做 UI 美化或新滤镜。

## 五、验收指标

- **兼容性**：NVIDIA / AMD / Intel / 混合显卡各至少 1 台；无黑屏；降级原因可见。
- **播放**：4K 零拷贝 NVIDIA ≈30 FPS；低 SR FPS 时保持 1x（允许跳帧）；<15 FPS 自动降档。
- **稳定**：1h 4K 播放 + 切档/seek/美颜/任务边播无崩溃；VRAM 不持续增长。
- **任务**：4K FullSource 峰值内存较当前下降（tile 目标 <1.2GB，待实测）。
- **分发**：安装/绿色包均可启动；缺 VC runtime、缺 cudart、缺 TensorRT 都有明确路径。
- **可诊断**：用户可一键导出 GPU/后端/版本/最近错误。

## 六、风险

1. **混合显卡黑屏**：legacy shared handle 跨 adapter；需要真实笔记本验证，代码上保留默认 adapter 逃生。
2. **可选 TensorRT 组件**：拆包会引入下载/校验/版本兼容问题；若工期紧，V0.3 先保留完整包。
3. **tile 4K**：tile 接缝、颜色一致性、内存/速度权衡，需要 A/B。
4. **2x/3x 模型**：可能没有兼顾速度/画质的 NCNN 模型；允许结论是“暂不支持”，不要硬塞。
5. **签名证书**：需要用户/组织提供，不能由代码解决。

## 七、已确认决策

1. V0.3 **Windows 优先**，移动端只做 spike，完整端放 V0.4。
2. 发布形态 **安装包 + 绿色 zip 两者都保留**。
3. TensorRT 在 V0.3 **先不拆可选组件**；先保证缺 cudart/TRT 自动回退，拆包放 V0.3.x。
4. 代码签名证书仍待组织提供；V0.3 beta 至少提供 SHA256、版本号和未签名提示。
5. 真人 2x/3x 作为 P1 评估，不阻塞 V0.3；模型质量/速度不达标则接受“仅 4x”。
